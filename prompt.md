Build and publish an artifact for KRI owners to review query results. Attached are kris_manifest.csv (one row per KRI: kri_id, name, owner, risk_category, risk_subcategory, description, formula, data_limitations, query_text, run_date, version, register_url, csv_name, current_status), kri_components.csv (kri_id, component, role, csv_column, unit, note), and one result CSV per KRI named by kri_id. The owner column is the accountable owner. The status scale is Green, Green early warning, Yellow, Red. Anything else, including blank, is shown as neutral "Not assessed".

Data design: store each KRI as one row in a database collection named kris, with the manifest fields plus a components list built from kri_components.csv. Upload each result CSV as an asset and store its url and file name on the row. Do not embed data in the HTML. Declare the db, assets, and downloads capabilities. Set the database rules so everyone who can open the page can read and only admins can write. Load the rows and upload the assets after publishing, and make the page handle an empty database.

Page: a searchable list with three filters: risk category, accountable owner, and data status (known limitations or none). Each list item shows the KRI ID, name, current status as a colored label that also shows the status text, risk category, accountable owner, and a tag when a data limitation exists. Use four distinct status colors that work in light and dark mode and never rely on color alone. The detail view shows the name, ID, current status, accountable owner, risk category and subcategory, run date, and version, prominently; the description; a highlighted note when data_limitations is not blank; the formula; a components table with component, role, latest value, prior value, and note, where latest and prior are the last two rows of that component's csv_column in the result CSV and a blank value displays as "Not available"; and the query in a block that can be collapsed, open by default. Hide the components table when a KRI has none. Also show a preview of the first 50 result rows with the status column colored on the same scale, a download button for the full CSV using the downloads capability, and a link to the KRI's register entry.

The page must be read-only. It must not store approvals or any viewer input. Approvals are recorded by owners as comments in a separate Google Doc register. Support light and dark mode and a narrow phone layout. After publishing, tell me what you could not verify.
